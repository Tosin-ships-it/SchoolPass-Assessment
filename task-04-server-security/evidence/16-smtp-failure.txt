4. DIAGNOSIS AND ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
Root Cause:
Google's mail infrastructure enforces Multi-Factor Authentication (MFA/2FA) on all
production accounts. When programmatic services (SMTP clients) authenticate using
an interactive user account password, Google deliberately rejects the authentication
with code 535-5.7.8 (InvalidSecondFactor).

Why This Is Expected (Brief Step 10 Alignment):
"Configure SMTP. Record your host and port. Expect the first attempt to fail.
Ours failed because Google rejected the login: the configuration held an ordinary
password rather than an application password. Capture that failure and the fix."

Remediation Required:
1. Log in to the Google Workspace / Gmail Security console.
2. Generate a dedicated 16-character "App Password" bound specifically to "SchoolPass SMTP".
3. Update `SMTP_PASS` in `.env` with the generated application token.
4. Verify that the SchoolPass error logger never exposes the raw app password in
   terminal logs or customer telemetry (verified: secrets masked with `***`).
