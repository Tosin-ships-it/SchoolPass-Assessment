   1. 8-Thread CPU Rig (Hypothetical Full Workstation Utilization):
      - Argon2id (8 threads):
        Theoretical Rate = 8 * 10.68 = ~85.4 guesses / second
        RAM Requirement = 8 * 64 MiB = 512 MiB RAM
      - SHA-256 (8 threads):
        Theoretical Rate = 8 * 666,667 = ~5,333,336 guesses / second (~5.33 MH/s)
        RAM Requirement = ~0 MiB

   2. Dedicated 64-Core High-End Cracking Server (e.g. AMD EPYC 7742):
      - Argon2id:
        Theoretical Rate = 64 * 10.68 = ~683 guesses / second
        RAM Requirement = 64 * 64 MiB = 4,096 MiB (4 GiB) RAM bandwidth-locked
      - SHA-256:
        Theoretical Rate = 64 * 666,667 = ~42,666,688 guesses / second (~42.6 MH/s)

   3. Consumer GPU Acceleration (e.g. Single NVIDIA RTX 4090):
      - SHA-256 on GPU:
        Because SHA-256 requires zero RAM and simple 32-bit bitwise logic,
        a modern RTX 4090 executing Hashcat easily achieves:
        Theoretical Rate = > 25,000,000,000 guesses / second (25 GH/s)
        Time to test an 8-character alphanumeric keyspace (2.18 * 10^14 combinations):
        Time = (2.18 * 10^14) / (2.5 * 10^10) = 8,720 seconds = ~2.4 hours!

      - Argon2id on GPU:
        Argon2id is strictly "memory-hard". Each hash instance requires 64 MiB
        of RAM with continuous memory lookups. A 24 GB VRAM GPU can physically fit
        at most:
        24,576 MiB / 64 MiB = 384 concurrent threads.
        Because GPU memory bus bandwidth becomes heavily saturated by random lookups,
        hash rates drop to approximately ~1,000 - 2,500 guesses/second per GPU.
        Time to test the same keyspace at 2,000 guesses/sec:
        Time = (2.18 * 10^14) / 2000 = 1.09 * 10^11 seconds = ~3,456 YEARS!

6. THE TIMING INVERSION PRINCIPLE
--------------------------------------------------------------------------------
The fundamental principle of secure password storage is the Asymmetric Timing
Inversion:

1. The Defender's Perspective (Legitimate User & Server):
   - A parent logs into SchoolPass once per day or session.
   - Spending ~94 ms on password verification represents a negligible, humanly
     imperceptible pause in the browser.
   - Cost to defender: Near zero.

2. The Attacker's Perspective (Stolen Database Offline Cracking):
   - If an attacker obtains a database dump, rate limiting, firewalls, and network
     protections no longer apply. The attacker attempts offline brute force.
   - To test 100 million dictionary words against one stolen Argon2id hash:
     Time = 100,000,000 / 10.68 guesses/sec = 9,363,295 seconds = ~108 DAYS.
   - To test the same 100 million dictionary words against a SHA-256 hash:
     Time = 100,000,000 / 666,667 guesses/sec = 150 seconds = 2.5 MINUTES (CPU),
     or < 0.01 SECONDS on a consumer GPU.

Conclusion: Making the hashing function deliberately slow and memory-intensive
imposes no measurable burden on legitimate users, while imposing catastrophic,
deterrent computational and hardware costs on an offline attacker.

--------------------------------------------------------------------------------
7. LIMITATIONS & SCOPE OF THIS BENCHMARK
--------------------------------------------------------------------------------
1. What This Proves:
   - Quantifies the actual CPU latency of Argon2id ($m=65536, t=3, p=1$) vs SHA-256
     on the local Intel i7-8650U test machine.
   - Confirms that SchoolPass's chosen algorithm satisfies OWASP recommendations for
     password storage latency (~100 ms).
   - Proves mathematically why fast hashes (SHA-256, MD5, SHA-1) are completely
     unsuitable for credential defense.

2. What This Does NOT Prove:
   - Does not measure multi-threaded server throughput under high concurrency.
   - Multi-core and GPU performance figures in Section 5.B are theoretical
     extrapolations based on architectural specifications, not measured results.
   - Does not account for specialized ASIC hardware, though Argon2id's memory-hardness
     is mathematically designed to minimize ASIC advantages.
