  - Overall isolated validation overhead is less than 0.01 milliseconds (10 microseconds).

5. CONTEXTUAL OVERHEAD & SECURITY TRADEOFF ANALYSIS
--------------------------------------------------------------------------------
In an end-to-end HTTP request to POST /api/auth/register:
  1. TCP & TLS handshake latency: 5 - 30 ms (network dependent)
  2. Next.js routing & middleware processing: 2 - 5 ms
  3. JSON body decoding & stream reading: ~0.005 - 0.008 ms
  4. Zod schema validation (validateJsonBody): ~0.007 - 0.012 ms (< 0.015 ms)
  5. Prisma ORM / PostgreSQL query (check duplicate email): 5 - 25 ms
  6. Argon2id password hashing (RFC 9106 recommended parameters): 90 - 100 ms
  7. Next.js after() background job scheduling: 0.2 - 0.5 ms
  8. Total End-to-End Latency: ~105 - 160 ms

Validation Cost Relative to Request Duration:
  - Zod validation constitutes: 0.0074 ms / 130 ms ≈ 0.0057% of total request time.
  - Hashing constitutes: ~95 ms / 130 ms ≈ 73.1% of total request time.
  - Database queries constitute: ~15 ms / 130 ms ≈ 11.5% of total request time.

Security Benefits Gained for ~7.1 µs (0.007 ms) CPU Cost:
  - Eliminates prototype pollution, type confusion, and missing property exceptions.
  - Prevents malformed, excessive, or unparseable inputs from reaching the database layer.
  - Rejects invalid registration requests before triggering expensive Argon2id hashing
    (93.6 ms) or database connection acquisition, protecting against validation-bypass DoS.


6. PRODUCTION MEASUREMENT LIMITATIONS & SCOPE BOUNDARIES
--------------------------------------------------------------------------------
Can genuine request-level before-and-after measurements be taken on live production routes?
  - Determination: NO.
  - Reason: Measuring the live /api/auth/register route without validation would require
    either:
    a) Modifying the production route code to remove `validateJsonBody`, or
    b) Inserting timing hooks into the production source files.
  - Both actions are strictly prohibited by assessment rules ("Do not modify SchoolPass
    application source code").
  - Furthermore, live execution against the active Next.js server triggers database writes
    against the live Neon PostgreSQL instance and attempts to dispatch real emails via Gmail SMTP,
    violating assessment safety rules.
  - Therefore, the request pipeline benchmark above was executed using Web Standard Request
    objects executing the actual `validateJsonBody` implementation in an isolated test harness.
  - Critical Standard: Isolated Zod timing (~7 - 15 µs) must NEVER be presented or
    misrepresented as total HTTP latency. Real HTTP latency is dominated by network transmission,
    framework middleware, and database/cryptographic I/O.
