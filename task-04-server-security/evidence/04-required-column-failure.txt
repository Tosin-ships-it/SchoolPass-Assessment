1. SCENARIO AND OBJECTIVE
--------------------------------------------------------------------------------
The assessment brief mandates demonstrating the exact failure mode when an engineer
or automated agent attempts to add a non-nullable (required) column to an existing
populated table without specifying a default value or backfill strategy.

In a database containing live rows, adding a column with NOT NULL constraint
violates relational integrity because all existing rows would instantaneously contain
NULL values for the new column, triggering a database-level constraint rejection.

6. TECHNICAL ANALYSIS & ARCHITECTURAL IMPLICATION
--------------------------------------------------------------------------------
Why This Fails:
Relational database management systems (RDBMS) enforce domain integrity on writes.
When a table contains 3 records and an ALTER TABLE operation introduces a NOT NULL
constraint without a default expression, the database engine cannot determine what
value to assign to existing rows. In raw PostgreSQL, this produces error:
  "column "phoneNumber" contains null values (SQLState 23502)"
Prisma's Schema Engine detects this hazard statically before issuing the ALTER TABLE,
halting the migration to protect data integrity and prevent service downtime.

Why This Distinguishes Engineers from Passive Agent Observers:
An inexperienced engineer or autonomous agent attempting an automated schema migration
against production would cause an immediate service crash or deployment lock.
The correct production protocol is the canonical three-step migration (Evidence 05).
