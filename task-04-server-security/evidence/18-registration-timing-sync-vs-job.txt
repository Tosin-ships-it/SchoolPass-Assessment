5. HOSTING LIFECYCLE: LOCAL NODE.JS VS VERCEL SERVERLESS PLATFORM
--------------------------------------------------------------------------------
Understanding the operational differences between local development and production hosting
is critical for defending Next.js after():

Local Development Environment (Node.js Process):
  - In local development (next dev or node server.js), Node.js runs as a long-lived, continuous
    process. The Node.js event loop remains active indefinitely across requests.
  - A simple un-awaited promise (e.g., sendEmail().catch(...)) will continue running in the
    event loop even after res.end() flushes the HTTP response.
  - Limitations in Dev: The developer does not experience serverless freeze bugs locally.
    A naive detached promise appears to "work" in local testing, hiding a critical defect
    that causes 100% email delivery failure in serverless production.

Production Hosting (Vercel Serverless Functions / AWS Lambda):
  - In serverless hosting, function containers are ephemeral. The runtime is designed to maximize
    resource efficiency and freezes (or terminates) the execution context the instant the HTTP
    response finishes sending.
  - If email delivery is dispatched using a detached promise without after(), the function
    runtime freezes mid-execution, terminating the TCP socket connection to the SMTP server.
    The email is never delivered.
  - How Next.js after() Solves This:
    Next.js after() interfaces directly with the platform's execution lifecycle (e.g., Vercel's
    waitUntil API). It registers the asynchronous task with the function container, instructing
    the hypervisor: "Flush the HTTP response to the client immediately, but DO NOT freeze this
    container until this background promise settles."
  - This architecture combines sub-150ms HTTP registration responses for Nigerian mobile users
    with 100% reliable background email dispatch on serverless infrastructure.
