1. THE ATTACK SCENARIO
--------------------------------------------------------------------------------
In Task 3, the application implemented client-side input validation on the frontend
registration form (enforcing two-word names, email format, password complexity, terms
acceptance, and password confirmation).

An attacker can completely bypass client-side validation by issuing raw HTTP requests
directly to the server using curl, Postman, or automated scripts, omitting legal terms
acceptance, using single-word names, or bypassing confirmation fields.

In Task 3, the server accepted this direct request with `HTTP 200 OK`.
In Task 4, every client-side rule is enforced again at the server boundary with Zod,
causing the exact same request to be rejected with `HTTP 400 Bad Request`.

--------------------------------------------------------------------------------
3. EXHAUSTIVE SERVER-SIDE ENFORCEMENT VERIFICATION
--------------------------------------------------------------------------------

Test Case A: Single-word name (`{"name": "BypassUser", ...}`)
  Response: HTTP/1.1 400 Bad Request
  Body:     {"error":"Please enter your first and last name."}
  Rule:     nameSchema enforces >= 2 words, >= 2 characters per word.

Test Case B: Omitted Terms of Service (`terms` / `acceptedTerms` omitted or false)
  Response: HTTP/1.1 400 Bad Request
  Body:     {"error":"You must accept the Terms of Service and Privacy Policy."}
  Rule:     parentRegisterSchema refinement mandates boolean true.

Test Case C: Mismatched Password Confirmation (`confirmPassword !== password`)
  Response: HTTP/1.1 400 Bad Request
  Body:     {"error":"Passwords do not match."}
  Rule:     parentRegisterSchema cross-field refinement check.

Test Case D: Database Side-Effects Audit
  Direct Prisma inspection verified:
  - Parent record:           NULL (Not created)
  - VerificationToken:       NULL (Not created)
  - StudentLinkRequest:      NULL (Not created)

--------------------------------------------------------------------------------
4. LESSON AND DEFENSE
--------------------------------------------------------------------------------
Client-side validation exists strictly for user experience (reducing latency and
preventing unnecessary network roundtrips). It is never a security control.
The server is the ultimate source of truth: every invariant, business rule, and
integrity constraint must be enforced at the backend boundary before reaching
domain models or storage.
